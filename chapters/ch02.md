## 2. 하드웨어 구성과 모델 구분

자동차형 로봇에서는 바퀴의 회전으로 이동하는 **구동(Drive, 드라이브)**과 진행 방향을 바꾸는 **조향(Steering, 스티어링)**이 서로 다른 기능이다. 후륜 구동은 뒤쪽 바퀴에서 추진력을 만들고, 조향 장치는 앞쪽 바퀴의 방향을 바꾸는 구조를 예로 들 수 있다. 그러나 실제 로봇에 좌·우 독립 모터가 있는지, 조향 서보가 어떤 단위로 제어되는지, 차체의 조향 링크 구조가 무엇인지는 모델별로 다르므로 확인 없이 확정하면 안 된다.

| 구분 | 물리적 의미 | 소프트웨어에서 표현할 값 | 실제 장비 확인 사항 |
|---|---|---|---|
| 조향부 | 진행 방향 변화 | `steer_deg` | 허용 범위·중립·부호 |
| 후륜 구동부 | 전후 방향 이동 | `speed_mps` | 모터 수·방향·속도 환산 |
| 제어기 | 명령 수신 및 구동 | `enabled` | 통신·타임아웃·에러 |
| 전원부 | 모터에 에너지 공급 | 코드 밖에서 관리 | 배터리·차단 장치 |
| 차체 | 바퀴 사이 기하 구조 | `wheelbase_m` | 실제 축간 거리 |

**중요:** 공개된 과거 알티노 제품 설명의 조향각 또는 모터 구조를 최신 **알티노 AI**의 확정 사양으로 전용하지 않는다. 이 교재의 0.18m, ±20°, 0.35m/s는 모두 **모의 실습용 가정**이다. 공식 SDK와 장비 제원을 확인하면 별도 장비 어댑터에서 검증한 값으로 교체한다.


## 3. 제어 흐름과 안전 계층

사용자 입력을 바로 모터 명령으로 전달하는 구조는 교육적으로도 위험하다. 명령이 허용 범위를 벗어나거나 통신이 끊기면 예상하지 못한 속도 또는 방향으로 움직일 수 있다. 따라서 **요청 명령 → 허용 조건 검사 → 제한값 적용 → 제어 출력** 순서를 분리한다.

```text
사용자/AI 명령(Command)
       │ steer_deg, speed_mps, enabled
       ▼
안전 게이트(sanitize) ── enabled=False → 0도·0m/s 목표
       │ 속도·조향 제한
       ▼
운동학 모의 모델(update) ── 위치·방향·속도 갱신
       │
       ▼
궤적 출력 / 테스트 검증
       ╳ 실제 모터 전송 경로 없음
```

`enabled`는 **명령 허용 플래그**일 뿐 하드웨어 긴급정지 장치가 아니다. 코드가 종료되거나 통신이 끊어졌을 때 실제 로봇이 멈춘다는 보장은 별도의 제어기 안전 기능, 통신 타임아웃 및 하드웨어 차단 회로가 있을 때만 성립한다. 모의 프로그램에서 `enabled=False`는 목표 속도를 0으로 바꾸지만 가감속 한계 때문에 모의 속도가 즉시 0이 되지는 않는다. **물리적 비상정지와 소프트웨어 목표 정지를 혼동하지 않는다.**


## 4. 좌표계·부호·단위

기본 좌표계는 시작 위치를 원점 `(x, y) = (0, 0)`으로, 초기 진행 방향을 +x축으로 정한다. 진행 방향 `heading_rad`는 라디안으로 저장하고, 왼쪽으로 반시계 방향 회전하면 양수로 증가한다고 정의한다. `steer_deg` 역시 왼쪽 조향을 양수, 오른쪽을 음수로 정의한다. 실제 장비의 서보 회전 부호와 일치한다는 뜻은 아니다.

| 변수 | 의미 | 단위 | 모의 기준 |
|---|---|---|---|
| `x_m`, `y_m` | 평면상의 위치 | m | 시작점 0,0 |
| `heading_rad` | 차체의 방향 | rad | 시작 방향 0 |
| `steer_deg` | 앞바퀴 조향각 | ° | 왼쪽 + |
| `speed_mps` | 전진 속도 | m/s | 전진 + |
| `dt_s` | 갱신 시간 간격 | s | 0.1 |
| `wheelbase_m` | 앞뒤 차축 간 거리 | m | 예시 0.18 |

라디안과 도는 서로 다른 각도 단위다. `math.radians(15)`는 15도를 라디안으로 바꾸며, 15°는 약 0.2618rad이다. `sin`, `cos`, `tan` 함수는 라디안을 입력받는다. 이 변환을 누락하면 조향 계산 결과가 크게 달라진다. 좌표계와 부호는 코드·도식·시험표 전체에서 동일하게 유지한다.


## 5. 자전거 운동학 모델의 의미

교육용 **Bicycle Model(바이시클 모델, 자전거 운동학 모델)**은 네 바퀴 자동차의 앞바퀴를 하나의 대표 바퀴로, 뒷바퀴를 하나의 대표 바퀴로 단순화한다. 타이어 미끄럼과 관성, 모터 토크를 생략하여 조향각과 속도가 차체 회전율에 미치는 영향을 직관적으로 확인한다.

**회전율:** `yaw_rate = speed × tan(steer_angle) / wheelbase`이며 단위는 rad/s이다. **위치 변화:** `Δx ≈ speed × cos(heading) × dt`, `Δy ≈ speed × sin(heading) × dt`이다. 본 예제는 한 구간의 중간 방향을 이용하여 `Δx`, `Δy`를 계산한다.

예를 들어 속도 0.20m/s, 조향 15°, 축간 거리 0.18m이면 회전율은 약 `0.20 × 0.2679 / 0.18 ≈ 0.298rad/s`이다. 0.1초 동안 방향은 약 0.0298rad, 즉 1.71° 바뀐다. 반대로 조향이 0°이면 `tan(0)`이 0이므로 방향은 바뀌지 않는다. 속도가 0이면 조향각만 주어도 이 운동학 모델에서는 방향이 변하지 않는다.

**모델의 한계:** 이 값은 실물 조향 성능을 예측한 시험 결과가 아니다. 실제 차량의 기어비, 구동 전류, 접지 상태, 휠 슬립, 좌우 모터 차이, 서보 오차, 배터리 전압을 반영하지 않는다. 실제 장비로 확장할 때는 속도 측정과 캘리브레이션이 필요하다.


## 6. 가감속 제한과 정지의 차이

목표 속도를 한 번에 바꾸면 기계적 충격과 미끄럼을 유발할 수 있다. 모의 모델은 한 시간 간격에서 바뀔 수 있는 속도의 크기를 `max_accel_mps2 × dt_s`로 제한한다. 가령 가속도 한계가 0.4m/s²이고 간격이 0.1초이면 한 번의 갱신에서 속도 변화는 최대 0.04m/s이다. 목표가 0.35m/s여도 첫 단계 속도는 0.04m/s, 다음 단계는 0.08m/s로 증가한다.

이때 명령을 정지로 바꾸면 목표 속도는 0이지만 현재 속도가 0.20m/s라면 첫 갱신 후 속도는 0.16m/s가 된다. 즉 **감속 정지**이며 **긴급 차단**이 아니다. 실제 로봇의 안전 정지 기능은 기계 제동·전원 차단·하드웨어 E-Stop(이 스톱, 비상정지) 등 장비 매뉴얼에 규정된 방법을 사용한다.

| 상황 | 모의 목표 | 해석 |
|---|---|---|
| `enabled=False` | 속도 0, 조향 0 | 명령 비활성화 |
| `speed_mps=0` | 속도 0 | 정상 감속 요청 |
| 통신 끊김 | 본 모의 코드에는 통신 없음 | 실제 장비에서 별도 타임아웃 필요 |
| 긴급 정지 | 구현되지 않음 | 별도 안전 하드웨어 필요 |

이 차이를 이해하면 이후 카메라 인식과 AI 판단에서 위험 신호를 발견했을 때 어떤 안전 제어를 요구해야 하는지 구체적으로 설계할 수 있다.


## 7. 실행 환경과 파일 준비

이번 차시는 외부 Python 패키지를 설치하지 않는다. Python 표준 라이브러리 `dataclasses`, `math`, `typing`, `unittest`만 사용하므로 인터넷이 없어도 실행할 수 있다. 프로젝트 구조에서 `codes/ch02/` 폴더에 `steering_sim.py`와 `test_steering_sim.py`를 둔다.

```bash
# Python 버전 확인: 실행 중인 인터프리터를 확인한다.

# 프로그램 실행: 실제 모터에 명령을 보내지 않는 모의 실습이다.
```

Windows 환경에서는 `python3` 대신 `py -3` 또는 `python` 명령을 사용한다. 두 파일이 같은 폴더에 있어야 테스트 코드의 `from steering_sim import ...`가 정상 작동한다. 파일명을 `math.py`, `typing.py`, `unittest.py`로 만들면 표준 라이브러리 이름과 충돌할 수 있으므로 피한다.

**실행 전 확인:** 프로그램은 시리얼 포트를 열지 않고 네트워크를 사용하지 않으며 실제 모터 출력 함수를 호출하지 않는다. 따라서 로봇을 연결하지 않은 PC에서도 동일한 알고리즘과 테스트를 실행할 수 있다.


## 8. 데이터 구조와 입력 명령 해설

`VehicleSpec`은 축간 거리, 최대 조향각, 최대 속도, 최대 가감속을 한 곳에 묶는다. `Command`는 사용자가 요청하는 조향각과 목표 속도, 명령 활성 여부를 담는다. `Pose`는 현재 위치·방향·속도 상태를 나타낸다. 이렇게 **설정값·명령값·상태값**을 구분하면 코드의 책임이 명확해진다.

`@dataclass(frozen=True)`가 붙은 `VehicleSpec`, `Command`는 생성 후 필드를 변경할 수 없는 값 객체로 취급한다. 명령 검증 결과를 기존 명령에 덮어쓰지 않고 새로운 `Command`로 반환하므로 요청값과 적용값을 비교하기 쉽다. `Pose`는 매 갱신마다 새로운 상태 객체를 만들어 기록한다.

**예제 해석:** `Command(15, 0.25, True)`는 왼쪽으로 15° 조향하고 0.25m/s의 속도를 목표로 하는 활성 명령이다. 반면 `Command(15, 0.25, False)`는 같은 수치를 담더라도 허용되지 않은 명령이므로 `sanitize()`에서 목표 조향과 속도를 모두 0으로 바꾼다.

입력 인터페이스를 이렇게 정의해두면 나중에 카메라 인식, 차선 추적, 수동 키보드 조작, AI 모델 출력이 모두 같은 `Command` 형식으로 연결될 수 있다. 실제 장비로 보낼 때는 그 다음 단계에 **검증된 제조사 SDK 어댑터**를 추가해야 한다.


## 9. 안전 제한 함수의 단계별 해설

`clamp(value, low, high)`는 숫자를 지정한 범위로 제한한다. 예를 들어 `clamp(30, -20, 20)`은 20을 반환하고, `clamp(-30, -20, 20)`은 -20을 반환한다. 이 연산은 `max(low, min(high, value))`로 구현할 수 있다. 먼저 상한을 적용하고 다음에 하한을 적용하는 형태다.

`sanitize()`는 명령 허용 여부를 가장 먼저 확인한다. 허용되지 않은 명령은 각도와 속도를 0으로 설정한다. 허용된 명령은 최대 조향각과 최대 속도 범위로 제한한다. 이 순서가 중요한 이유는 **안전 조건을 확인하지 않고 입력 수치부터 처리하면 비활성화 명령의 의미가 흐려질 수 있기 때문**이다.

| 입력 | 적용 결과 | 이유 |
|---|---|---|
| `(50°, 2m/s, True)` | `(20°, 0.35m/s, True)` | 상한 제한 |
| `(-50°, -2m/s, True)` | `(-20°, -0.35m/s, True)` | 하한 제한 |
| `(18°, 0.3m/s, False)` | `(0°, 0m/s, False)` | 정지 우선 |
| `(0°, 0.2m/s, True)` | `(0°, 0.2m/s, True)` | 허용 범위 |

**주의:** `clamp()`는 입력 숫자가 정상이라는 전제를 사용한다. 실무에서는 NaN, 무한대, 형식 오류, 오래된 명령, 인증되지 않은 송신자까지 추가 검증해야 한다. 본 실습은 핵심 개념에 집중한 최소 구조다.


## 10. 모의 주행 시나리오와 예상 결과

기본 시나리오는 0.1초 간격으로 총 30번 갱신한다. 1~10회는 직진, 11~20회는 왼쪽 조향, 21~30회는 정지 명령이다. 매 단계는 현재 속도에서 목표 속도까지 가감속 한도를 적용한 뒤 위치와 방향을 갱신한다.

```text
0~1초     직진  steer=0°   목표속도 0.25m/s
1~2초     좌회전 steer=15°  목표속도 0.25m/s
2~3초     정지  enabled=False → 목표속도 0m/s
```

| 단계 | x(m) | y(m) | 방향(°) | 속도(m/s) |
|---|---:|---:|---:|---:|
| 0 | 0.000 | 0.000 | 0.00 | 0.000 |
| 10 | 0.184 | 0.000 | 0.00 | 0.250 |
| 20 | 0.428 | 0.046 | 21.32 | 0.250 |
| 30 | 0.490 | 0.070 | 21.32 | 0.000 |

이는 제공된 모의 코드의 **실행 검증 결과**이며 실제 알티노 AI의 주행 측정값이 아니다. 왼쪽 조향 동안 `y`와 방향이 증가하고, 마지막 10단계 동안 속도가 감소해 0에 도달하는지 확인한다. 실험 결과가 다르면 코드·Python 버전·파라미터 변경 여부를 먼저 확인한다.


## 11. 코드 풀이 — 상태 갱신 알고리즘

`update(pose, cmd, dt_s, spec)`는 한 시간 간격의 상태를 계산하는 함수다. 먼저 시간 간격이 0보다 크고 1초 이하인지 확인한다. 그다음 축간 거리가 양수인지 검사한다. 잘못된 값이면 계산을 계속하지 않고 `ValueError`를 발생시킨다.

안전 검증을 통과한 목표 속도와 현재 속도의 차이를 계산하고, 한 단계에 허용되는 가감속 크기로 제한한다. 갱신된 속도와 조향각을 이용해 회전율을 구한 뒤, 시간 구간의 중간 방향으로 x·y 이동량을 계산한다. 마지막으로 새 위치·방향·속도를 `Pose`로 반환한다.

**한 단계 수치 예제:** 초기 속도 0m/s, 목표 속도 0.25m/s, 최대 가속도 0.4m/s², 간격 0.1초라면 첫 단계 속도는 0.04m/s이다. 조향각이 0°이면 첫 이동량은 x축으로 0.004m, y축으로 0m가 된다. 2단계 속도는 0.08m/s이고 이동량은 x축으로 0.008m이다.

모델은 이동을 수치적으로 근사한다. 시간 간격을 너무 크게 하면 곡선의 오차가 커질 수 있다. 따라서 `dt_s`를 0.1초에서 0.05초로 바꿔 동일한 총 시간을 유지하는 실험은 유용한 심화 과제다. 이때 명령 반복 횟수도 두 배로 늘려야 공정한 비교가 된다.

## 18. 전체 실행 코드 — `steering_sim.py`

아래 코드는 파일에 저장된 원본과 동일하다. 실물 제어 명령을 송신하지 않는다.

```python
"""02차시: 실제 장비 명령을 전송하지 않는 조향·후륜 구동 모의 실습."""
from dataclasses import dataclass
from math import radians, tan, sin, cos
from typing import Iterable

@dataclass(frozen=True)
class VehicleSpec:
    wheelbase_m: float = 0.18  # 예시 모델 값; 실물 제원 아님
    max_steer_deg: float = 20.0  # 교육용 제한값; 알티노 AI 확정 사양 아님
    max_speed_mps: float = 0.35  # 모의 속도 제한
    max_accel_mps2: float = 0.4  # 모의 가감속 제한

@dataclass(frozen=True)
class Command:
    steer_deg: float
    speed_mps: float
    enabled: bool = False

@dataclass
class Pose:
    x_m: float = 0.0
    y_m: float = 0.0
    heading_rad: float = 0.0
    speed_mps: float = 0.0


def clamp(value: float, low: float, high: float) -> float:
    if low > high:
        raise ValueError('low must not exceed high')
    return max(low, min(high, value))


def sanitize(cmd: Command, spec: VehicleSpec) -> Command:
    """정지 조건을 우선하고 조향·속도 요청을 제한한다."""
    if not cmd.enabled:
        return Command(0.0, 0.0, False)
    return Command(clamp(cmd.steer_deg, -spec.max_steer_deg, spec.max_steer_deg),
                   clamp(cmd.speed_mps, -spec.max_speed_mps, spec.max_speed_mps), True)


def update(pose: Pose, cmd: Command, dt_s: float, spec: VehicleSpec) -> Pose:
    """자전거 운동학 모델(교육용 근사): 실제 차량 동역학 아님."""
    if dt_s <= 0 or dt_s > 1:
        raise ValueError('dt_s must be in (0, 1]')
    if spec.wheelbase_m <= 0:
        raise ValueError('wheelbase must be positive')
    safe = sanitize(cmd, spec)
    dv = clamp(safe.speed_mps - pose.speed_mps,
               -spec.max_accel_mps2 * dt_s, spec.max_accel_mps2 * dt_s)
    speed = pose.speed_mps + dv
    # 중점 적분: 회전하는 동안의 진행 방향을 반영한다.
    yaw_rate = speed * tan(radians(safe.steer_deg)) / spec.wheelbase_m
    mid_heading = pose.heading_rad + yaw_rate * dt_s / 2
    return Pose(pose.x_m + speed * cos(mid_heading) * dt_s,
                pose.y_m + speed * sin(mid_heading) * dt_s,
                pose.heading_rad + yaw_rate * dt_s, speed)


def simulate(commands: Iterable[Command], dt_s: float = 0.1,
             spec: VehicleSpec = VehicleSpec()) -> list[Pose]:
    poses = [Pose()]
    for command in commands:
        poses.append(update(poses[-1], command, dt_s, spec))
    return poses


def demo() -> None:
    spec = VehicleSpec()
    commands = ([Command(0, 0.25, True)] * 10 +
                [Command(15, 0.25, True)] * 10 +
                [Command(0, 0, False)] * 10)
    path = simulate(commands, 0.1, spec)
    print('step | x(m) | y(m) | heading(deg) | speed(m/s)')
    for i in (0, 10, 20, 30):
        p = path[i]
        print(f'{i:4d} | {p.x_m:5.3f} | {p.y_m:5.3f} | '
              f'{p.heading_rad * 180 / 3.141592653589793:12.2f} | {p.speed_mps:10.3f}')
    print('DRY RUN ONLY — no hardware commands were sent')


if __name__ == '__main__':
    demo()

```


## 19. 전체 자동 테스트 — `test_steering_sim.py`

아래 코드는 별도 테스트 파일과 동일하다.

```python
"""표준 라이브러리만 사용하는 자동 검증."""
import unittest
from math import isclose
from steering_sim import Command, Pose, VehicleSpec, clamp, sanitize, simulate, update

class SteeringTests(unittest.TestCase):
    def setUp(self):
        self.spec = VehicleSpec()

    def test_clamp(self):
        self.assertEqual(clamp(30, -20, 20), 20)
        self.assertEqual(clamp(-30, -20, 20), -20)

    def test_stop_priority(self):
        self.assertEqual(sanitize(Command(18, .3, False), self.spec), Command(0, 0, False))

    def test_limit(self):
        self.assertEqual(sanitize(Command(50, 2, True), self.spec), Command(20, .35, True))

    def test_straight(self):
        p = update(Pose(), Command(0, .2, True), .1, self.spec)
        self.assertGreater(p.x_m, 0)
        self.assertAlmostEqual(p.y_m, 0)

    def test_turn(self):
        p = update(Pose(speed_mps=.2), Command(15, .2, True), .1, self.spec)
        self.assertGreater(p.heading_rad, 0)
        self.assertGreater(p.y_m, 0)

    def test_acceleration(self):
        p = update(Pose(), Command(0, .35, True), .1, self.spec)
        self.assertAlmostEqual(p.speed_mps, .04)

    def test_invalid_dt(self):
        with self.assertRaises(ValueError):
            update(Pose(), Command(0, 0, False), 0, self.spec)

    def test_invalid_wheelbase(self):
        with self.assertRaises(ValueError):
            update(Pose(), Command(0, 0, False), .1, VehicleSpec(wheelbase_m=0))

    def test_sequence(self):
        poses = simulate([Command(0, .2, True)] * 5)
        self.assertEqual(len(poses), 6)
        self.assertTrue(isclose(poses[0].x_m, 0))

    def test_stop_is_not_instant(self):
        p = update(Pose(speed_mps=.2), Command(0, 0, False), .1, self.spec)
        self.assertGreater(p.speed_mps, 0)  # 모의 감속 한계; 실제 긴급정지 성능 아님
```

## 적대적 검증 반영 — 비정상 명령의 처리

`sanitize()`는 조향·속도 명령이 유한한 실수인지 먼저 검사한다. `NaN` 또는 `inf`를 클램핑하면 정상적인 큰 명령으로 변환될 수 있으므로 **그런 입력은 `enabled=False`인 0속도 안전 정지 요청으로 바꾼다**. `dt_s`와 현재 위치·속도 상태에도 비정상 수치가 있는지 검사한다.

| 공격성 입력 | 원래 위험 | 수정 후 기대 결과 |
|---|---|---|
| 조향 `NaN`, 정상 속도 | 조향 한계 +20°로 변환 | `Command(0,0,False)` |
| 정상 조향, 속도 `inf` | 최대 속도로 변환될 수 있음 | `Command(0,0,False)` |
| 시간 간격 `NaN` | 위치 계산에 비정상값 전파 | `ValueError` |

이 결과는 교육용 운동학 시뮬레이터의 안전 조건 시험이며, 실제 모터의 전원 차단·긴급 정지 성능을 입증하지 않는다.
