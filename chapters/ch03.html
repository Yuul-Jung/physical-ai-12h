01 | 차시 개요와 실습 성공 기준

이 차시는 카메라가 제공하는 2차원 영상 프레임과 라이다가 제공하는 각도별 거리 측정값을 구분하고, 두 종류의 데이터를 Python에서 확인하는 과정이다. 카메라는 물체의 색·형상·질감을 기록하지만 단일 영상의 픽셀만으로 절대거리를 직접 알 수 없다. 2차원 평면 라이다는 지정 각도 방향의 거리를 제공하지만 물체의 색상이나 문자 내용을 제공하지 않는다. 두 센서는 상호 보완 관계이다.

필수 성취 기준: (1) 카메라 프레임의 가로·세로·채널을 설명한다. (2) 모의 라이다 측정값에서 무효값을 제외한다. (3) 각도·거리 데이터를 x·y 좌표로 변환한다. (4) 전방 최단거리와 측정 실패를 구별한다. (5) CSV 및 PNG를 저장하고 확인한다.

60분 운영: 0~10분 센서와 데이터 흐름, 10~25분 영상 생성·확인, 25~45분 라이다 각도·거리·좌표 실습, 45~55분 전방 안전거리 판단, 55~60분 결과 제출 및 오류 확인. 실제 카메라 연결과 라이브 시각화는 장비·시간이 확보되었을 때 수행하는 선택 심화이다.

필요물: Python 3, NumPy, OpenCV, 텍스트 편집기, 저장 공간. 기본 실습은 로봇 없이 수행 가능하다. 실제 알티노 AI의 카메라와 라이다에 접근하는 제조사 SDK는 이 차시에서 검증하지 않았다. 로봇 주행 명령은 포함하지 않는다.

제출물: demo_camera.png, scan.csv, 콘솔 출력 3줄, 무효 데이터 필터링 설명 3문장. 시험 결과가 실제 장비 센서값이 아니라 모의 데이터임을 표시한다.

02 | 카메라·라이다·제어기의 역할 분리

카메라는 광학계와 이미지 센서가 빛을 받아 픽셀 배열을 만드는 장치이다. 라이다는 레이저의 반사 신호를 이용하여 거리를 추정하는 장치이다. 센서 드라이버는 원시 데이터 수신과 장치별 프로토콜 처리를 담당하고, 응용 프로그램은 영상 분석이나 거리 판단을 수행한다. 센서 데이터를 읽는 것과 차량을 움직이는 것은 서로 다른 책임이다.

[카메라] → [영상 입력/드라이버] → [프레임 배열] → [시각화/인식]
[라이다] → [센서 드라이버] → [각도·거리 배열] → [필터/좌표/장애물 판단]
                                         ↓
                                 [판단 결과·상태 출력]
                                         ↓ (별도 승인·검증 후)
                                   [주행 제어 계층]

기본 예제는 입력 장치가 없어도 동일한 데이터 처리 과정을 이해할 수 있도록 합성 이미지와 모의 스캔을 만든다. 따라서 센서 제조사에 종속되지 않는다. 장치 연결 시에는 입력 계층만 실제 카메라 또는 라이다 드라이버로 교체하고, 이후 처리 코드는 재사용하는 구조를 권장한다.

관찰 포인트: 영상 데이터는 행·열·색 채널을 가진 배열이다. 스캔 데이터는 각도 시작값, 각도 간격, 거리 배열을 함께 가져야 의미가 있다. 거리 배열만 복사하면 어느 방향의 장애물인지 복원할 수 없다. 센서가 서로 다른 시점에 측정한 데이터라면 동시 측정이라고 가정해서는 안 된다.

응용 질문: 카메라에서 빨간 물체가 보인다는 사실만으로 그 물체가 0.5m 앞에 있다고 단정할 수 있는가? 라이다가 0.5m를 측정했다는 사실만으로 그것이 신호등이라고 판별할 수 있는가? 두 질문 모두 추가 정보가 필요하다.

03 | 영상 프레임의 데이터 구조

영상 프레임은 일반적으로 (높이, 너비, 채널) 순서의 배열로 표현된다. 예제의 크기는 (360, 640, 3)이며, 전체 색상 요소는 360 × 640 × 3개이다. uint8 형식의 일반적인 8비트 채널 이미지라면 한 요소가 1바이트이므로 이미지 배열 자체의 데이터는 약 691,200바이트이다. PNG 파일 크기는 압축 때문에 다를 수 있다.

OpenCV의 일반적인 컬러 프레임은 BGR(파랑·초록·빨강) 순서를 사용한다. image[:] = (40, 40, 40)은 모든 픽셀의 세 채널을 회색으로 채운다. cv2.rectangle과 cv2.circle은 사각형과 원을 그린다. 이 코드는 실제 카메라를 촬영하는 것이 아니라 프레임과 동일한 형태의 테스트 이미지를 생성한다.

import numpy as np
image = np.zeros((360, 640, 3), dtype=np.uint8)
print(image.shape)  # (360, 640, 3)
print(image.dtype)  # uint8

실습: 이미지의 너비를 640에서 320으로 변경하고 저장한다. 배열의 크기는 (360, 320, 3)으로 달라진다. shape의 순서를 (너비, 높이, 채널)로 해석하면 좌표 계산과 크기 조절에서 오류가 발생한다. 픽셀 좌표의 원점은 일반적으로 이미지 좌측 위이고 x는 오른쪽, y는 아래쪽으로 증가한다.

확인: 합성 영상에 원과 사각형이 나타나야 한다. 실제 장면이나 차선이 나타나는 것이 아니다. 영상에 텍스트가 그려져 있어도 OCR(문자 인식)을 수행한 것은 아니다.

04 | 카메라 입력을 여는 절차

실제 일반 카메라 또는 영상 파일은 cv2.VideoCapture로 열 수 있다. 카메라 번호 0은 흔한 기본값이지만 장비마다 다르다. 제조사 전용 스트림이 별도 프로토콜을 사용하면 단순 카메라 번호로 접근되지 않을 수 있다. 알티노 AI의 카메라가 VideoCapture(0)으로 열리는지는 미검증이다.

import cv2
cap = cv2.VideoCapture(0)
try:
    if not cap.isOpened():
        raise RuntimeError('카메라 열기 실패')
    ok, frame = cap.read()
    if not ok or frame is None:
        raise RuntimeError('프레임 읽기 실패')
    print(frame.shape)
finally:
    cap.release()

isOpened()는 입력 소스 열기에 성공했는지 확인한다. read()는 성공 여부와 영상 배열을 반환한다. 프레임을 읽지 못하면 이전 화면을 현재 화면으로 오인하지 않아야 한다. release()는 장치 점유를 해제한다. 실제 시스템에서는 읽기 실패, 시간 초과, 재연결 정책을 추가해야 한다.

장치 점검 순서: 장치 연결 → OS에서 인식 확인 → 다른 프로그램의 카메라 점유 확인 → 입력 번호 또는 경로 확인 → 단일 프레임 획득 → 저장된 PNG 확인. 헤드리스 서버에서는 imshow() 창이 표시되지 않을 수 있으므로 imwrite()로 파일을 저장하는 방식이 유용하다.

실습 명령: python sensor_lab.py --camera 0 --out outputs/ch03은 범용 카메라 입력을 시도한다. 카메라가 없거나 권한이 없으면 예외가 발생한다. 기본 모의 실습은 --camera 인자를 빼고 실행한다.

05 | 라이다 스캔 메타데이터 해석

2차원 라이다의 대표적인 데이터 표현은 시작 각도 angle_min, 각도 증가량 angle_increment, 측정 거리 배열 ranges이다. ROS의 sensor_msgs/msg/LaserScan 메시지는 여기에 종료 각도, 최소·최대 측정거리, 시간 정보와 선택적 반사 강도도 포함한다. 이 교재의 Scan 클래스는 개념 학습을 위해 각도를 도(degree) 단위로 저장한다. ROS 표준 메시지의 각도는 라디안(radian) 단위이므로 그대로 대입하면 안 된다.

각도 계산: angle_i = angle_min_deg + i × angle_step_deg. 예제는 시작 각도 -90°, 간격 10°, 총 19개 측정값이다. 첫 번째 값은 -90°, 10번째 값(인덱스 9)은 0°, 마지막 값은 +90°에 대응한다. 이 수치는 실제 알티노 AI의 스캔 범위나 분해능을 뜻하지 않는다.

인덱스 각도 예제 거리 의미
0 -90° 2.8m 측면 방향
8 -10° 0.9m 전방 왼쪽/오른쪽 중 한쪽
9 0° 0.6m 정면
10 +10° 0.8m 반대쪽 전방
18 +90° 2.8m 반대 측면

부호 방향은 좌표계 정의에 의존한다. ROS 표준 평면 좌표계에서 x가 전방이고 z가 위쪽이면 양의 각도는 반시계 방향이다. 실물 로봇에서 센서가 반대로 설치되거나 회전하면 외부 좌표 변환이 필요하다.

실습: sample_scan()의 values[9]를 0.6에서 1.2로 변경하고 전방 최솟값을 다시 확인한다. 주변 값 0.8과 0.9가 있으므로 전방 최솟값은 0.8m로 바뀐다.

06 | 거리 유효성 검사와 결측값 처리

라이다 데이터에는 측정 실패, 반사 부족, 범위 초과 등으로 인해 inf, nan 또는 측정 범위 밖의 숫자가 들어올 수 있다. 이 값을 무조건 장애물이 없다는 뜻으로 해석하면 위험하다. 이 차시에서는 math.isfinite()로 유한한 숫자만 선택하고, 최소·최대 유효거리 범위를 검사한다.

from math import isfinite

def valid_distance(value, minimum=0.05, maximum=8.0):
    return isfinite(value) and minimum <= value <= maximum

for distance in [0.6, float('inf'), float('nan'), 0.01, 9.0]:
    print(distance, valid_distance(distance))

예상 결과는 0.6만 True이고 나머지는 False이다. 실제 센서의 최소·최대 거리는 제품 사양과 설정에 따라 다르므로 예제의 0.05~8.0m를 실제 사양으로 사용하지 않는다. 데이터가 모두 무효라면 nearest_front()는 None을 반환한다. None은 안전하다는 뜻이 아니라 판단할 수 없다는 뜻이다.

중요한 예외: 일부 장치의 무효 거리 표현은 0, 음수 또는 별도 상태 코드일 수 있다. 실제 센서 드라이버와 메시지 명세를 먼저 확인해야 한다. 유효 거리라도 반사 특성, 유리, 검은 표면, 경사면 등으로 오차가 발생할 수 있다. 이 교재는 센서의 정확도를 보증하지 않는다.

실습: 모든 측정값을 float('inf')로 변경한다. CSV에는 헤더만 기록되고, 전방 최단거리는 None이 되어야 한다. 실제 주행 제어 계층에서는 이러한 상태를 별도의 센서 오류 또는 안전 정지 조건으로 취급하는 정책이 필요하다.

07 | 극좌표에서 직교좌표로 변환

라이다는 보통 방향(각도)과 거리로 주변 물체를 나타낸다. 지도나 그래프에 점을 표시하려면 극좌표를 직교좌표로 변환한다. 센서 중심을 원점으로 두고 정면을 x축 양의 방향으로 정하면 x = r cos(θ), y = r sin(θ)이다. Python의 math.sin과 math.cos는 라디안을 받으므로 math.radians()로 도 단위를 변환한다.

from math import radians, cos, sin
angle_deg = 90
r = 2.0
theta = radians(angle_deg)
x = r * cos(theta)
y = r * sin(theta)
print(round(x, 3), round(y, 3))  # 0.0 2.0

정면 0°의 거리 0.6m는 (x, y) = (0.6, 0.0)이 된다. +90° 방향의 거리 2m는 (0, 2)가 된다. 좌표계 방향을 잘못 정의하면 장애물 위치가 좌우로 뒤집힌다. 센서의 위치가 차체 중심에서 떨어져 있다면 센서 좌표를 차체 좌표로 변환하는 추가 작업이 필요하다.

수치 오차: cos(90°)의 계산 결과는 부동소수점 표현 때문에 정확히 0이 아니라 매우 작은 수가 될 수 있다. 따라서 부동소수점 비교는 == 0 대신 허용오차를 사용한다. 자동 테스트는 assertAlmostEqual을 이용한다.

실습: -90°, 0°, +90° 각각 거리 1m인 세 점의 좌표를 계산한다. 기대 위치는 (0,-1), (1,0), (0,1)이다. 이는 센서 좌표계의 점이며 세계 좌표계의 위치는 아니다.

08 | 전방 장애물 거리 판단

전방 안전거리를 평가하려면 전체 스캔에서 가장 가까운 점을 찾는 것이 아니라 전방 각도 영역을 먼저 선택해야 한다. 예제는 -20°~+20°의 유효 측정값 중 최소 거리를 선택한다. 이 범위는 교육용 가정이며 실제 차량의 폭, 조향각, 제동거리, 센서 장착 위치에 따라 달라져야 한다.

scan = sample_scan()
front_min = scan.nearest_front(half_angle_deg=20)
print(front_min)  # 0.6

전방 측정값이 0.6m이면 장애물이 0.6m 떨어져 있다는 측정 결과를 얻은 것이다. 이것만으로 곧바로 '주행 가능/불가'를 확정할 수는 없다. 제동거리에는 속도, 제동 성능, 제어 지연, 통신 지연, 노면 상태, 측정 오차가 영향을 준다. 특히 센서가 None을 반환하는 경우 999m 같은 임의의 큰 숫자로 대체해 안전 판정을 내려서는 안 된다.

교육용 상태 구분 예: None → SENSOR_UNKNOWN, 거리 < 임의 임계값 → NEAR_OBJECT, 그 외 → MEASURED_CLEAR. 이 상태명은 실제 알티노 AI SDK의 API가 아니라 응용 프로그램에서 사용할 수 있는 설명용 개념이다. 본 차시의 예제는 실제 모터 명령을 보내지 않는다.

실습: 전방 각도 범위를 ±5°, ±20°, ±45°로 바꾸어 최솟값을 비교한다. 주변 측정값이 바뀌지 않으면 0°의 0.6m가 모든 범위에 포함되어 결과가 동일할 수 있다. 특정 측면의 거리를 더 짧게 수정하면 각도 범위에 따라 결과가 달라진다.

09 | CSV 저장과 데이터 재현성

센서 데이터를 파일로 저장하면 실물 장비가 없는 환경에서도 같은 입력으로 알고리즘을 반복 검증할 수 있다. save_scan_csv()는 각도, 거리, x, y를 CSV(쉼표로 구분된 표 데이터)로 기록한다. CSV 첫 줄은 angle_deg,range_m,x_m,y_m이다. 각 행은 유효 측정값 한 개를 나타낸다.

angle_deg,range_m,x_m,y_m
-90.0000,2.8000,0.0000,-2.8000
... (중간 데이터 생략)
0.0000,0.6000,0.6000,0.0000

예제의 원시 스캔은 19개 값이지만 inf, nan 2개를 제외한 유효 점 17개만 기록한다. 따라서 헤더 포함 18줄이 저장된다. 무효값을 버리면 후속 분석이 간단하지만 원본 데이터가 사라진다. 실제 프로젝트에서는 원시 데이터 파일과 정제 데이터 파일을 구분하여 보관하는 편이 좋다.

재현성 기록: 실습 날짜, 센서 모델, 측정 단위, 각도 기준, 데이터 샘플 수, 유효값 필터 조건, 프로그램 버전, 파일 생성 시간을 함께 기록한다. 실제 센서가 제공하는 타임스탬프가 있다면 시스템 시간과 혼동하지 않는다. 이번 CSV에는 타임스탬프가 없으므로 시간 동기화 분석에는 사용할 수 없다.

실습: scan.csv를 텍스트 편집기 또는 스프레드시트로 열어 0° 행의 x가 0.6이고 y가 0인지 확인한다. nan과 inf가 출력 파일에 남아 있지 않은지도 확인한다.

전체 실행 코드 — sensor_lab.py

"""03차시: 실제 로봇 제어가 없는 카메라·라이다 학습용 예제."""
from dataclasses import dataclass
from math import cos, sin, isfinite, radians
from pathlib import Path
import argparse
import csv

@dataclass(frozen=True)
class Scan:
    angle_min_deg: float
    angle_step_deg: float
    ranges_m: tuple[float, ...]
    min_m: float = 0.05
    max_m: float = 8.0

    def points(self):
        """유효한 측정값을 (각도, 거리, x, y)로 반환."""
        if self.angle_step_deg <= 0 or self.min_m <= 0 or self.max_m <= self.min_m:
            raise ValueError('스캔 메타데이터가 올바르지 않습니다')
        for i, distance in enumerate(self.ranges_m):
            if not isfinite(distance) or not self.min_m <= distance <= self.max_m:
                continue
            angle = self.angle_min_deg + i * self.angle_step_deg
            theta = radians(angle)
            yield (angle, distance, distance * cos(theta), distance * sin(theta))

    def nearest_front(self, half_angle_deg=20):
        """전방 부채꼴 유효 거리의 최솟값. 유효 측정이 없으면 None."""
        if not 0 <= half_angle_deg <= 180:
            raise ValueError('전방 각도 범위 오류')
        front = [d for a, d, _, _ in self.points() if abs(a) <= half_angle_deg]
        return min(front) if front else None


def sample_scan():
    """-90°부터 +90°까지 10° 간격의 모의 스캔."""
    values = [2.8] * 19
    values[8], values[9], values[10] = 0.9, 0.6, 0.8
    values[2], values[17] = float('inf'), float('nan')
    return Scan(-90, 10, tuple(values))


def save_scan_csv(scan, path):
    """좌표 변환 결과를 CSV로 기록."""
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    with path.open('w', newline='', encoding='utf-8') as f:
        writer = csv.writer(f)
        writer.writerow(['angle_deg', 'range_m', 'x_m', 'y_m'])
        for row in scan.points():
            writer.writerow([f'{v:.4f}' for v in row])
    return path


def create_demo_frame(path, width=640, height=360):
    """카메라 없이 생성 가능한 테스트 영상 한 장."""
    import cv2
    import numpy as np
    image = np.zeros((height, width, 3), dtype=np.uint8)
    image[:] = (40, 40, 40)  # OpenCV BGR 순서
    cv2.rectangle(image, (100, 90), (260, 260), (0, 180, 255), -1)
    cv2.circle(image, (440, 170), 75, (50, 220, 50), -1)
    cv2.putText(image, 'CAMERA DEMO', (120, 45), cv2.FONT_HERSHEY_SIMPLEX,
                1.0, (255, 255, 255), 2)
    path = Path(path)
    path.parent.mkdir(parents=True, exist_ok=True)
    if not cv2.imwrite(str(path), image):
        raise OSError('이미지 저장 실패')
    return path, image.shape


def capture_one_frame(source, path):
    """실제 연결된 일반 카메라 또는 영상 파일에서 한 프레임 저장."""
    import cv2
    source = int(source) if str(source).isdigit() else source
    cap = cv2.VideoCapture(source)
    try:
        if not cap.isOpened():
            raise RuntimeError('영상 입력을 열 수 없습니다')
        ok, frame = cap.read()
        if not ok or frame is None:
            raise RuntimeError('프레임을 읽을 수 없습니다')
        path = Path(path)
        path.parent.mkdir(parents=True, exist_ok=True)
        if not cv2.imwrite(str(path), frame):
            raise OSError('프레임 저장 실패')
        return path, frame.shape
    finally:
        cap.release()


def main():
    parser = argparse.ArgumentParser(description='03차시 카메라·라이다 데이터 실습')
    parser.add_argument('--out', default='outputs/ch03')
    parser.add_argument('--camera', help='실제 카메라 번호(0) 또는 영상 파일 경로')
    args = parser.parse_args()
    out = Path(args.out)
    scan = sample_scan()
    print('전방 최소 유효 거리(m):', scan.nearest_front())
    print('유효 라이다 점 수:', len(list(scan.points())))
    print('라이다 CSV:', save_scan_csv(scan, out / 'scan.csv'))
    if args.camera is None:
        path, shape = create_demo_frame(out / 'demo_camera.png')
    else:
        path, shape = capture_one_frame(args.camera, out / 'camera_frame.png')
    print('카메라 이미지:', path, '배열 형상:', shape)

if __name__ == '__main__':
    main()

11 | 오류 점검·테스트·안전

문제 1 — 카메라를 열 수 없음: 연결 상태, 카메라 번호, 사용 권한, 다른 프로그램의 점유, 영상 파일 경로를 순서대로 확인한다. 제조사 전용 카메라는 일반 USB 웹캠과 다른 방식일 수 있다. 카메라가 없어도 모의 실습으로 전환할 수 있다.

문제 2 — 라이다 전방 거리가 None: 전방 범위에 유효한 점이 없다는 뜻이다. '장애물 없음'과 구분한다. 센서 상태와 측정 범위, 데이터 형식을 확인해야 한다.

문제 3 — 좌표가 좌우 반전: 각도 단위(도/라디안), 양의 회전 방향, 센서 장착 방향을 확인한다. ROS LaserScan의 각도 단위와 예제의 단위가 다르다는 점을 주의한다.

문제 4 — CSV 행 수가 예상보다 적음: 무효 측정값이 필터링되었는지 확인한다. 필터링 전 19개, 후 17개라는 차이는 예제에 의도적으로 포함되었다.

문제 5 — 영상 크기와 파일 크기 혼동: 배열의 바이트 수와 압축 PNG의 디스크 크기는 같지 않다. 영상 배열의 shape와 dtype를 확인한다.

안전: 본 차시에서 로봇을 움직이지 않는다. 센서 테스트를 위해 실제 차량을 주행시켜야 한다면 별도 승인된 제어 절차, 저속 제한, 긴급 정지, 안전 구역, 보호자를 확보해야 한다. 센서 데이터 하나만으로 실제 주행 안전을 보증하지 않는다.

자동 테스트: python -m unittest discover -s codes/ch03 -p 'test_*.py' -v를 실행한다. 9개 테스트는 스캔 각도, 유효값 필터, 직교좌표, CSV 저장, 이미지 생성을 검증한다. 테스트 통과는 실제 카메라·라이다 장비 연결의 검증을 의미하지 않는다.

전체 자동 테스트 코드 — test_sensor_lab.py

import math
import tempfile
import unittest
from pathlib import Path
from sensor_lab import Scan, sample_scan, save_scan_csv, create_demo_frame

class TestSensorLab(unittest.TestCase):
    def test_angle_count(self):
        self.assertEqual(len(sample_scan().ranges_m), 19)
    def test_front_distance(self):
        self.assertAlmostEqual(sample_scan().nearest_front(), 0.6)
    def test_nonfinite_filtered(self):
        self.assertEqual(len(list(sample_scan().points())), 17)
    def test_empty_front(self):
        self.assertIsNone(Scan(90, 10, (1.0, 2.0)).nearest_front(10))
    def test_invalid_step(self):
        with self.assertRaises(ValueError):
            list(Scan(0, 0, (1.0,)).points())
    def test_invalid_range(self):
        self.assertEqual(list(Scan(0, 10, (0.01, 99, math.inf, math.nan)).points()), [])
    def test_cartesian(self):
        a, d, x, y = next(Scan(90, 1, (2.0,)).points())
        self.assertAlmostEqual(x, 0, places=6)
        self.assertAlmostEqual(y, 2, places=6)
    def test_csv(self):
        with tempfile.TemporaryDirectory() as d:
            p = save_scan_csv(sample_scan(), Path(d) / 'a.csv')
            self.assertEqual(len(p.read_text().splitlines()), 18)
    def test_image(self):
        with tempfile.TemporaryDirectory() as d:
            p, shape = create_demo_frame(Path(d) / 'a.png')
            self.assertTrue(p.exists())
            self.assertEqual(shape, (360, 640, 3))

if __name__ == '__main__':
    unittest.main()

적대적 검증 반영 — 라이다 전방 각도 순환

라이다가 0°~360° 각도를 사용하는 경우 350°와 -10°는 같은 방향이다. 기존 전방 검사인 abs(angle) <= 20은 350°를 전방으로 보지 못했다. 수정 코드에서는 ((angle + 180) % 360 - 180)을 사용하여 -180°~180° 범위로 정규화한 후 전방 영역을 판단한다.

# (변경) 각도 순환 경계 350° → -10°
front = [d for a, d, _, _ in self.points()
         if abs((a + 180) % 360 - 180) <= half_angle_deg]

시험 입력 Scan(350, 5, (0.4, 0.2, 1.0))은 전방 350°, 355°, 360° 측정으로 해석되어 최소 거리 0.2m를 반환해야 한다. 실제 센서의 0° 방향이 로봇 정면과 일치하는지는 제조사 좌표계 문서로 확인해야 한다.
